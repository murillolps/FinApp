Notas sobre o modelo

  • Multi-usuário desde o início: toda entidade tem user_id. Isolamento via row-level security no banco.
  • ACCOUNTS entra no MVP como conta única ("Carteira Principal") criada automaticamente no signup. Mas o schema já suporta múltiplas contas pra evolução futura.
  • RECURRENCES não duplica linhas — gera transações concretas só na data certa (ou sob demanda na UI). A tabela do mês mostra projeções "virtuais" calculadas em runtime.
  • Saldo não é coluna armazenada: é calculado por SUM(entradas) − SUM(saídas) sobre as transações até a data. Pra performance futura: criar view materializada ou snapshot mensal.
  • Soft delete: categorias e contas usam archived em vez de delete físico, pra não quebrar transações antigas.

Fluxo de Telas (User Flow)

Como o usuário navega entre as telas no MVP.

flowchart TD
    A[Login / Cadastro] -->|primeiro acesso| B[Onboarding rápido
- nome
- saldo inicial]
    A -->|usuário existente| C[Dashboard]
    B --> C
    C -->|+ Entrada / + Saída| D[Modal: Nova Transação]
    C -->|ver detalhes| E[Transações do Mês]
    E -->|+ Nova| D
    E -->|editar linha| D
    C -->|menu| F[Categorias]
    C -->|menu| G[Recorrências]
    C -->|menu| H[Relatórios]
    F -->|+ Nova| F2[Modal: Nova Categoria]
    G -->|+ Nova| G2[Modal: Nova Recorrência]
    D -->|salvar| C
    F2 -->|salvar| F
    G2 -->|salvar| G
Princípio de UX: tudo o que o usuário faz no dia a dia (lançar entrada/saída) tem que estar a 1 clique de distância do dashboard. Configurações (categorias, recorrências) ficam no menu, fora do caminho principal.
